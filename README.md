# 이미테이션 게임 (Imitation Game)

> 술집에 모인 스파이 후보생들이 서로에게 예/아니오 질문을 던져, 상대가 누구인지 먼저 알아맞히는 심리 추리 대결

**배포: Cloudflare Workers (Static Assets)** — 이 브랜치에 push 하면 GitHub Actions 가 자동 배포한다
([`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)).

기획: [`GDD.md`](GDD.md) · 덱 검증 리포트: [`DECK.md`](DECK.md)

---

## 지금 어디까지 됐나

| 단계 | 상태 |
|---|---|
| **M0. 덱 확정** | ✅ 15장 데이터 + C1~C4 검증 + 완전 탐색 |
| **M1. 로컬 프로토타입** | ✅ 규칙 전체 구동, 화면 1~10 |
| **M2. 온라인 대전** | ✅ **방 코드로 최대 4인** — Durable Objects + WebSocket, 서버 권위 판정 |
| **M5. 4인 확장** | ✅ **서바이벌 모드** — 대상 선택 질문·지목, 탈락 후 관전 |
| M3. 아트 · 사운드 | ⬜ 초상 15장, 토큰에 맞춘 캐릭터 설정 집필 |
| M4. 강화 | ⬜ 턴 제한 시간, 자유 대사 모더레이션 |

세 가지 모드로 플레이할 수 있다.

- **온라인 대전** — 호스트가 방을 만들면 4자리 코드가 나오고, 최대 세 명이 그 코드로 들어온다
- **연습 · 봇과 대전** — 혼자서 규칙을 익힌다. 봇은 코인을 쓰고 진실을 말하는 선택도 실제로 한다
- **2인 · 한 기기 번갈아** — 기기를 넘길 때마다 화면이 가려진다 (핫시트)

로컬 두 모드는 네트워크 없이 돌아간다.

## 개발

```bash
npm install        # wrangler 하나뿐 (개발 의존성)

npm test           # 덱 검증 + 엔진 검증
npm run test:online  # 온라인 통합 검증 (먼저 npm run preview 로 서버를 띄울 것)
npm run validate   # 덱 제약 C1~C5 + 최적 결정 트리 완전 탐색

npm start          # http://localhost:5173  — 의존성 없는 정적 서버 (빠른 확인용)
npm run preview    # 빌드 후 wrangler dev — 실제 Cloudflare 런타임으로 확인
npm run check      # 테스트 + 빌드 + 배포 드라이런 (배포 전 점검)
npm run deploy     # 테스트 + 빌드 + wrangler deploy
```

**번들러도 트랜스파일도 없다.** 브라우저가 ESM 을 그대로 읽는다.
`npm run build` 는 `dist/` 에 브라우저가 요청하는 파일만 모을 뿐이다 (11개 파일 · 163 KB).
저장소 루트를 그대로 올리지 않는 이유는 `node_modules` 와 테스트 스크립트까지 딸려 가기 때문이다.

그래서 **같은 엔진이 브라우저(로컬 모드)와 Durable Object(온라인) 양쪽에서 그대로 돈다** — 규칙을 두 번 쓰지 않는다.

## 규칙 구현에서 지킨 것

### D6 — 코인을 쓴 답변은 시스템의 판정 밖으로 나간다

이 게임의 심장이다. 구현에서 문자 그대로 지켰다.

- 코인을 **쓰지 않은** 답변 → 엔진이 답변자 카드로 진실값을 계산한다. **거짓말이 물리적으로 불가능하다**
- 코인을 **쓴** 답변 → 답변자가 지정한 Y/N 과 대사를 그대로 기록한다.
  **진실값을 계산하지도, 저장하지도, 검사하지도 않는다**

로그 항목에 `wasLie` 같은 필드는 **존재하지 않는다.** 엔진 검증에 이 사실을 확인하는 테스트가 있다
(`로그에 진실 여부 필드가 존재하지 않는다`). 결과 화면에도 `✓진실 / ✕거짓` 라벨을 붙이지 않는다 —
대신 양쪽 카드를 전부 공개해 플레이어가 직접 대조하게 한다.

> 저장하지 않는 것은 샐 수 없다. 이 규칙 결정이 그대로 가장 견고한 보안 설계가 된다 (GDD 6-6).

### 자동 적용은 「거짓일 수 없는 정보」에만

추리 노트에서 후보를 자동으로 지우는 것은 다음 세 가지뿐이다.

| 자동 | 근거 |
|---|---|
| 내 카드 | 카드는 중복 배분되지 않는다 → 상대가 나일 수 없다 |
| 공개된 토큰 | 지목 실패로 유출된 토큰은 사실이다 |
| 코인이 **쓰이지 않은** 답변 | 시스템이 진실을 강제하므로 거짓일 수가 없다 |

**코인이 쓰인 답변은 절대 자동 적용하지 않는다.** `🪙 검증 불가` 배지와 함께 두고,
적용할지는 플레이어가 직접 판단한다. 적용한 단서는 칩을 클릭해 언제든 해제할 수 있다 —
상대의 거짓말을 뒤늦게 눈치챘을 때 되돌리는 장치다.

### 수치 질문 — 이상 / 이하, 임계값은 구간 경계에만

키·몸무게·나이는 **이상과 이하 양쪽으로** 물을 수 있다. 임계값은 구간 경계에만 놓인다.

| | 키 | 몸무게 | 나이 |
|---|---|---|---|
| 이상 | 175 · 185 | 65 · 80 | 28 · 36 |
| 이하 | 174 · 184 | 64 · 79 | 27 · 35 |

「174 이하」와 「175 이상」은 **같은 자리를 가르는 뒤집힌 표현**이다. 정보량은 같고 말맛만 다르다 —
짧은 쪽을 쫓을 때 「이하」가 자연스럽기에 둘 다 열어두었고, 눈금자에서 이상↔이하를 전환해도
손잡이 자리가 튀지 않는다.

**경계가 아닌 값(예: 180cm)은 열지 않았다.** 팜플렛에는 구간(`175–184`)만 적혀 있어서,
"180 이상?"에 NO를 들어도 그 구간의 제인·이본·루퍼트·하워드 중 누구를 지울지 판단할 수 없다 —
후보를 논리적으로 제거할 수 없는 질문은 질문이 아니다 (GDD D1). 이 제약은 검증으로 고정해 두었다:
`npm run validate` 의 **C5** 가 구간 내부를 쪼개는 질문이 하나라도 생기면 실패한다.

> 📌 GDD 6-4 는 질문을 12종으로 적고 있다. 이상/이하를 열면서 18종이 되었으므로,
> 기획서를 갱신하실 때 이 표를 반영하면 된다. 덱 데이터와 D1 제약 자체는 그대로다.

### 3~4인 — 서바이벌

인원에 따라 승리 조건 자체가 달라진다. 엔진의 `modeFor(playerCount)` 하나가 그 분기를 쥐고 있다.

| | 2인 (`duel`) | 3~4인 (`survival`) |
|---|---|---|
| 지목 성공 | 반격 턴 (D4) — 후공에게 무승부 기회 | **그 사람만 탈락**, 판은 계속된다 |
| 지목 3회 실패 | 패배 | **자기가 탈락** |
| 승리 | 상대를 맞히고 반격을 넘긴 쪽 | **마지막까지 남은 한 명** |
| 코인 | 2개 | **3개** |

3인 이상이면 **「누구에게」를 먼저 고른다.** 질문 모달과 지목 모달 맨 위에 상대 칩이 뜨고,
칩마다 그 사람에 대한 **남은 후보 수**가 붙는다 — 누구를 몰아붙일지 한눈에 보라는 뜻이다.
추리 노트도 상대별로 완전히 분리되어 있어서(`notes[나][상대]`), 상대 탭을 바꾸면 표·단서 칩이 통째로 갈린다.

**탈락자의 카드는 전원에게 공개된다.** 카드는 중복 배분되지 않으므로 남은 사람들의 후보에서 자동으로 빠진다
(추리 노트의 `☠` 행). 탈락한 사람은 판을 계속 지켜보되 행동 버튼이 잠긴다.
결과 화면에는 네 사람의 카드와 함께 **탈락 순서**가 「누구에게 들켰는지 · 몇 턴이었는지」까지 적힌다.

### 핫시트 비밀 유지

한 기기에서 2인이 플레이할 때, **다음에 화면을 봐야 할 사람이 바뀌면 무조건 가림막이 뜬다.**
선공은 무작위라 기기를 든 사람과 첫 행동 주체가 다를 수 있으므로, 첫 카드가 열리기 전에도
「내가 ○○입니다」 확인을 거친다.

## 아직 확인되지 않은 것 (플레이 테스트 항목)

GDD 10장의 미결 사항 중, **이 빌드로 확인해야 할 것**들이다.

1. **정직한 블러핑이 실제로 쓰이는가** — 아무도 「코인 쓰고 진실 말하기」를 하지 않으면
   코인은 단순 반전 도구로 퇴화하고, 상대는 코인 표시를 보고 뒤집어 읽으면 그만이 된다.
   **D5·D6 전체가 걸린 유일한 검증 항목이다.**
2. **실전 게임 길이** — "각자 6~8질문, 총 12~16턴"은 손계산 추정이다. 논리 하한 4질문 대비 실제 배수
3. **턴 제한 시간** — 대사 입력 때문에 답변 시간이 길어진다는 점을 감안해야 한다

## 배포 — Cloudflare Workers

Worker 는 `/api/*` 만 처리한다. 정적 자산 요청은 Worker 를 거치지 않고 자산 시스템이 바로 응답하므로,
게임 화면을 여는 비용은 정적 사이트와 같다.

### 자동 배포 (GitHub Actions)

이 브랜치에 push 하면 [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) 이
`npm ci → npm test → npm run build → wrangler deploy` 순으로 돈다.
**덱 검증(C1~C5)이나 엔진 테스트가 하나라도 실패하면 배포하지 않는다.**
(온라인 통합 검증은 서버를 띄워야 해서 CI 에는 넣지 않았다 — 로컬에서 `npm run test:online` 으로 돌린다.)

저장소 **Settings → Secrets and variables → Actions** 에 아래 두 개가 있어야 한다
([Cloudflare 공식 안내](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/)와 이름이 동일하다):

| Secret | 값 |
|---|---|
| `CLOUDFLARE_API_TOKEN` | Edit Cloudflare Workers 권한을 가진 API 토큰 |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare 계정 ID |

### 로컬에서 수동 배포

```bash
npm run check    # 테스트 + 빌드 + 드라이런 — 배포 전 점검
npm run deploy   # 실제 배포
```

로컬에서 돌리려면 최초 1회 인증이 필요하다. 둘 중 하나를 쓰면 된다.

```bash
npx wrangler login                  # 브라우저 OAuth (로컬 개발 머신)
# 또는 CI·헤드리스 환경 — 위 Actions Secrets 와 같은 값
export CLOUDFLARE_API_TOKEN=...
export CLOUDFLARE_ACCOUNT_ID=...
```

`compatibility_date` 는 wrangler 에 들어 있는 workerd 가 지원하는 최신 날짜에 맞춰야 한다.
더 뒤로 잡으면 `wrangler dev`/배포가 런타임을 띄우지 못한다.

## 온라인 대전 — 어떻게 만들어졌나

**방 하나 = Durable Object 인스턴스 하나 + WebSocket.**

```
POST /api/room             방 만들기 → { code, playerId }
POST /api/room/:code/join  코드로 입장 → { playerId }
GET  /api/room/:code/ws    WebSocket (게임 진행)
```

호스트가 방을 만들면 **4자리 코드**가 나온다. 헷갈리는 글자(`0/O`, `1/I`)를 뺀 32자에서 뽑으므로
전화로 불러 줘도 헷갈리지 않는다. 게스트는 소문자로 넣어도 되고 하이픈이 섞여도 된다.
**한 방에 최대 4명**이 들어가고, 방장이 준비 상태를 확인한 뒤 시작한다 — 2명이면 대결, 3명 이상이면 서바이벌이다.

### 서버가 판정한다

DO 는 요청을 직렬화해 처리하므로 턴제 게임의 동시성 문제가 애초에 생기지 않는다.
무엇보다 **룰 엔진을 DO 안에서 그대로 돌린다.** 그 결과 GDD 6-6 이 M4 로 미뤄뒀던
서버 권위 판정을 처음부터 얻었다.

| 취약점 | 원래 계획 (클라이언트 판정) | 지금 (Durable Object) |
|---|---|---|
| 상대 카드 열람 | 보안 규칙으로 차단 | **애초에 클라이언트로 보내지 않는다** |
| 코인 없이 거짓말 | 변조 가능 — M4 로 유예 | **서버가 진실값을 계산** |
| 지목 판정 조작 | 변조 가능 — M4 로 유예 | **서버가 판정** |
| 남 대신 답변 | — | **서버가 발신자를 확인하고 거절** |

두 가지를 특히 조심해서 만들었다.

1. **`viewFor(state, playerId)`** — 내보내기 전에 상대의 `cardId` 를 지운다.
   게임이 끝나야 `result.cards` 로 모두가 함께 공개된다. 지목 실패로 공개된 토큰은
   사실이므로 `revealedTokens` 로 미리 풀어서 넣어 준다 (카드 없이는 슬롯을 토큰으로 못 바꾸므로).
   **서바이벌에서 탈락한 사람의 `cardId` 는 예외적으로 남긴다** — 규칙상 전원에게 공개되는 정보다.

2. **`authorize(game, playerId, action)`** — 엔진의 `apply()` 는 「호출자가 올바른 플레이어」임을
   전제할 뿐 확인하지 않는다. 이 확인이 없으면 **상대 대신 `ANSWER` 를 보내 진실을 흘리게 만드는
   조작**이 가능하다. `CONTINUE` 도 클라이언트에게 열지 않았다 — 답변 공개 후 턴 넘김은
   서버가 알람으로 처리한다.

★ D6 은 서버에서도 동일하다. 코인을 쓴 답변의 진실값은 **계산하지도 저장하지도 않는다.**

### 끊겨도 돌아온다

브라우저마다 토큰을 하나 만들어 `localStorage` 에 둔다. 새로고침하거나 잠시 끊겨도
같은 토큰으로 **원래 자리·원래 카드**로 복귀한다. 소켓은 지수 백오프로 자동 재연결한다.
하이버네이션 API 를 쓰므로 대기 중에는 DO 가 메모리에서 내려가도 연결이 유지된다.

### 검증 (`npm run test:online`)

실제로 뜬 서버에 소켓을 붙여 2인전 한 판을 끝까지 두고, 이어서 4인 방을 따로 열어 본다. **41건.**

```
방 만들기 · 입장     4자리 코드 · 소문자 허용 · 없는 코드 404 · 정원 초과 409 · 재입장
연결 · 대기실        입장 안 한 토큰은 소켓 거부 · 토큰 미유출 · 준비/방장 강제
카드 배분           ★ 상대 cardId 가 null · 페이로드 어디에도 상대 카드 없음
권한                남의 카드 확인 거절 · 남의 턴 거절 · ★ 남 대신 답변 거절 · CONTINUE 거절
진행                진실 강제 · 양쪽 로그 일치 · 서버 알람 자동 턴 넘김 · ★ wasLie 없음
종료 · 재접속        끝나야 양쪽 카드 공개 · 같은 토큰 → 같은 자리 · 방장만 재시작
4인 서바이벌        5번째 거절 · 코인 3개 · ★ 나머지 셋의 카드가 전부 가려짐
                   ★ 대상 지정 질문 · 제3자 답변 거절 · ★ 질문/답변 전원 공개
                   ★ 지목 성공 → 그 사람만 탈락 · 탈락자 카드만 공개 · 턴 건너뛰기 · 행동 잠금
```

브라우저 네 개(각각 별도 컨텍스트)로 실제 4인전도 끝까지 확인했다 — 대기실부터 결과 화면까지,
대상 칩·노트 탭·탈락 배너가 모두 동작하고 **탈락자 외에는 누구의 카드도 남의 화면에 나오지 않는다.**
